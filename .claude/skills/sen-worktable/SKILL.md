# sen-worktable — AI作業台の初期セットアップ

## Purpose

毎回プロンプトを書くのではなく、**環境＝器を作る**（第25条・第11章）。
コードを書かない人でも、会議録整理・営業資料・週報・CSV分析・マニュアル化などを
「見て → 計画 → 小さく実行 → 差分を見る → 検証 → Skillに残す」の順で回せる土台を用意する。
成果は速さ（時短）だけでなく、**やれることの範囲の拡張**にある。

## Non-negotiables

1. **いきなり作らない。** まず現状フォルダを読み、提案（構成・CLAUDE.md草案・Skill候補）を出す。
   作成・変更は承認後。既存の上書き・削除は必ず確認（第4条 摩擦配置）。
2. **成功条件で動く（第3部 5.5）。** 「何を満たせば完了か」を先に定義してから着手させる。
3. **生成と識別を分ける（第3部 5.6）。** 出したものは人間が差分で確認し、納得したものだけ Accept。
   「AIを信じる」のではなく「AIが作った作業を確認できる状態」にする。
4. データ主権（第5条）：機密・個人情報はローカル境界の内側で扱う。外部送信は停止案件。

## Inputs

- 誰の・どんな仕事か（営業／経営／人事／マーケ／研究 等）
- よく繰り返す作業（毎日10分かかっている単発作業が最良の第一歩）
- 既存フォルダ・資料の場所（あれば）

## Workflow

1. 対象フォルダを読む（変更しない）。現状・不明点・リスクを短く提示。
2. **作業台フォルダ構成**を提案する（最小構成の雛形）：
   - `inbox/` 元資料を入れる
   - `briefs/` 要約・方針を置く
   - `outputs/` 完成物を置く
   - `templates/` よく使う型を置く
   - `archive/` 終わったものを置く
   - `.claude/skills/` 自分専用の手順（Skill）を置く
3. **CLAUDE.md 草案**を出す（毎回守るルール。例）：
   - いきなり変更しない／まず計画を出す
   - 削除・上書き・外部送信は承認を取る
   - 事実と仮説を分ける
   - 成果物は `outputs/` に置く
   - 納品前に誤字・根拠・CTA を確認する
4. **最初に作るべき Skill を1つ**提案する（繰り返す作業＝Skill化の第一候補）。例：
   `meeting-actions`（会議録→ToDo）／`csv-insight`（CSVから示唆）／`quality-gate`（納品前チェック）。
   まず1つだけ作り、翌日また使い、安定したら型として残す。
5. 承認後、最小 diff で作成。差分を見せ、納得したものだけ適用。

## Output

- 現状把握（構成・不明点・リスク）
- 提案するフォルダ構成
- CLAUDE.md 草案（コピペ可能な形）
- 最初の Skill 候補1つ（用途・入力・出力・成功条件つき）
- 次の一手（どの繰り返し作業を次に Skill 化するか）
